# Агент Гамма · Тренажёр ученика

Ты — агент **Гамма**. Сейчас ученик получает только один наводящий вопрос, а весь портрет сделан для учителя.

Твоё направление замыкает петлю на стороне ученика:
1. ошибка;
2. лестница подсказок без готового ответа;
3. самостоятельное исправление;
4. задания под слабое место.

В журнал при этом попадает новый сигнал, которого учитель сейчас не видит: исправляет ли ученик ошибку сам по вопросу (скорее невнимательность) или ему нужен разобранный пример (скорее непонимание).

**Кратко**

- **Результат:** страница «Тренажёр» — разбор своей ошибки и 3–5 заданий под слабое место; лестница из трёх подсказок; блок «Тренажёр» в портрете учителя.
- **Объём:** этап A — примерно 3 часа, этап B — 3–4 часа.
- **Зависимости:** нет.

## Общее для всех агентов

> Этот раздел одинаковый во всех шести заданиях: Альфа, Бета, Гамма, Дельта, Эпсилон, Дзета. Вы работаете параллельно в одном репозитории, каждый в своей ветке.

### Проект

**Портрет ученика** — MVP команды на хакатоне VENTUREHACK 2026, трек «Образование». Веб-приложение для учителя математики на Streamlit. Автопроверка домашних работ по алгебре 7–9 классов (SymPy) записывает в *журнал наблюдений* ошибки, способы решения и привычки ученика. Из журнала и комментариев учителя собирается *портрет* «где слаб и как работать» и *карта класса*. Интерфейс на русском и казахском.

Репозиторий: https://github.com/SatbayevAman/venture-hack. Подробности — в `README.md`.

### Принципы — нарушать нельзя

1. **Модель только на входе и на выходе.** Языковая модель распознаёт почерк, размечает свободный текст учителя и переформулирует готовые советы. Всё, что считает и решает, — обычный код, поэтому любой вывод воспроизводим.
2. **Только словарь тегов.** Выводы об ученике — только коды из `core/tags.py`. Неизвестный тег `db.add_observation` превращает в `other` или `teacher_other`. Новый вид вывода — это новый тег в словаре: название, совет учителю и совет ученику на `ru` и `kk`.
3. **Доказательство у каждого вывода:** работа, задача, строка, цитата. Меньше 3 случаев — пометка «мало данных» вместо вывода.
4. **Тон.** Описываем действия («в 4 работах из 6 нет проверки»), а не характер. Наводящий вопрос никогда не называет ответ. Версия для ученика — мягкая.
5. **Приватность.** Псевдонимы вместо имён. Фото не сохраняются — только строки текста. Синтетические данные везде подписаны как синтетические.
6. **Без ключа API всё работает.** Новая функция с языковой моделью обязана иметь офлайн-путь или аккуратно отключаться с объяснением.
7. **Два языка.** Каждая строка интерфейса — через `L("рус", "қаз")`, в словарях — поля `ru` и `kk`. Все новые казахские тексты перечисли в отчёте: их вычитает носитель языка.

### База и журнал

Таблицы в `core/db.py`: `students`, `assignments`, `problems`, `submissions` (`source`: `synthetic` или `live`), `attempts`, `steps`, **`observations`**, `teacher_comments`, `tags`. Портрет нигде не хранится: он каждый раз считается заново из `observations`.

Одна строка журнала — это контракт между проверкой и портретом:

```json
{"student_id": 1, "submission_id": 42, "problem_id": 27, "line_no": 1, "kind": "error",
 "tag": "lost_root", "skill": "quadratic", "evidence": "x² = 7x  →  x = 7",
 "detail": {"f": "x", "division": true}, "source": "auto", "confidence": 0.9}
```

Поля и смысл существующих значений не меняются. Новые значения `source` допустимы (например, `practice`): `portrait.build` учитывает только `auto` и `teacher`, поэтому числа портрета от них не меняются.

### Как работать параллельно с другими агентами

1. Ветка `agent/<имя>` от свежего `main`, небольшие осмысленные коммиты. Порядок: этап A целиком → все тесты проходят → PR; этап B — следующими коммитами после него.
2. Свой код — в своих новых файлах (см. раздел «Границы»). В общих файлах — только точечные вставки в указанных местах. Не переформатируй, не переименовывай и не переноси чужой код.
3. Сигнатуры существующих функций не меняй. Можно добавить необязательный параметр, если при значении по умолчанию поведение прежнее.
4. Новые таблицы — не в `db.SCHEMA`, а в своём модуле: константа `SCHEMA` и функция `ensure_schema(conn)` с `CREATE TABLE IF NOT EXISTS`. Твой код вызывает её перед обращением к таблице. Существующие таблицы не меняй, никаких `ALTER TABLE`.
5. Страница интерфейса — модуль `ui/<имя>.py` с функцией `render(...)`. `ui/__init__.py` — пустой файл; если его ещё нет, создай пустым. В `app.py` добавляются только импорт, ключ в `PAGES`, подпись в `PAGE_NAMES` и запись в словаре страниц в последней строке.
6. Новые зависимости — только если без них никак: строкой в `requirements.txt` с комментарием и с объяснением в отчёте. Python 3.9+: `from __future__ import annotations`, без `match`.
7. Тесты — в `tests/test_<имя>.py`, без сети и без ключа API (языковую модель подменяй через `monkeypatch`). Существующие тесты не правь.
8. `README.md` не трогай. Описание своей работы — в `docs/<имя>.md`; ссылку в README добавит человек при слиянии.
9. Конфликты при слиянии ожидаются только в местах регистрации: импорты в начале `app.py`, `PAGES`, `PAGE_NAMES`, словарь страниц в последней строке `app.py`, блоки словаря `TAGS`. Они аддитивны: оставляй обе стороны.

## Этап A — обязательный минимум

### A1. Подсказки — `core/hints.py`

1. Функция `hint(first_error: dict, level: int, lang: str, statement: str, skill: str) -> str`:
   - **уровень 1** — `tags.question_for(first_error, lang)`;
   - **уровень 2** — правило `RULES[tag][lang]`: 2–3 предложения о том, почему такой переход ошибочен и как делать надёжно. Правила нужны для всех 6 тегов ошибок: `lost_root`, `extra_root`, `sign`, `fsu`, `calc`, `other`. Для неизвестного тега (новые темы Беты) — общее правило «проверь переход подстановкой числа»;
   - **уровень 3** — разобранный пример `practice.worked_example(tag, skill, avoid=statement, seed)`: задача той же семьи с другими числами, полное верное решение по строкам, ключевой шаг отмечен, например «← здесь выносим x за скобки, а не делим на него».
2. Функция `leaks_answer(text, true_answer) -> bool`. Тест гарантирует, что подсказки уровней 1 и 2 не содержат правильных корней задачи ученика.

### A2. Генератор задач — `core/practice.py`

1. Шаблоны с параметрами — по образцу `_quad_variants` в `core/seed.py`. По семье шаблонов на каждый тег:

   | Тег (навык) | Шаблоны |
   |---|---|
   | `lost_root` (quadratic) | x² = kx; ax² = bx; x(x − p) = q(x − p) |
   | `extra_root` (quadratic) | x²/(x − p) = (sx − t)/(x − p) с одним посторонним корнем |
   | `sign` (linear) | ax + b = cx + d; a(x − p) + b = cx − d |
   | `fsu` (simplify) | (a + p)² − (a − p)(a + p); (x − p)² + 2px |
   | `calc` (quadratic) | x² − sx + p = 0 с целыми корнями |
   | `skip_steps` (linear) | многошаговые уравнения с двумя парами скобок |
   | `check_done` (любой) | обычная задача + требование «сделай проверку подстановкой»; засчитывается, только если в результате проверки есть привычка `check_done` |

2. У каждой задачи: `statement`, `kind`, `skill`, `reference` (строки эталонного решения), `answer`. Числа целые и «удобные»; запись как в сиде: `−`, `²`, `·`.
3. **Самопроверка генератора.** Эталон каждой сгенерированной задачи прогоняется через `checker.check_problem`: должно быть `first_error is None` и `correct is True`. Иначе задача отбрасывается и генерируется другая.
4. Функции `generate(tag, skill, n, seed) -> list[dict]` (без повторов) и `worked_example(tag, skill, avoid, seed)`.
5. `targets_for(conn, student_id, lang)` — что тренировать, в порядке приоритета:
   - первая рекомендация из `portrait.build(...)["recs"]`, если её тег есть в таблице шаблонов;
   - иначе ошибки с пометкой «мало данных»;
   - иначе — «Всё хорошо, вот задачи на закрепление»: смешанный набор.

### A4. Сигнал в журнал

1. Новые теги (kind `habit`) в `core/tags.py`:
   - `self_fixed` — «Исправил(а) сам(а) по наводящему вопросу» / «Бағыттаушы сұрақ бойынша өзі түзетті»;
   - `fixed_after_rule` — «Исправил(а) после подсказки-правила» / «Ереже-кеңестен кейін түзетті»;
   - `needs_example` — «Понадобился разобранный пример» / «Талданған мысал қажет болды»; советы учителю и ученику на `ru` и `kk`, например учителю — разобрать тему на уроке с опорой на пример.
2. Когда задача завершена, запиши наблюдение:
   ```python
   db.add_observation(conn, student_id, submission_id, problem_id, line_no, "habit", tag, skill,
                      evidence, detail, source="practice", confidence=0.9)
   ```
   - `evidence` — например, «x² = 7x: ошибка «Потеря корня» в строке 1»;
   - `detail` — `{"hint_level": k, "error_tag": исходный_тег, "item_id": id}`;
   - `submission_id` — исходная работа в режиме «разбор своей ошибки», иначе `NULL`.
3. **Правило исхода** — после ошибки задача решена верно:
   - открыта только ступень 1 → `self_fixed`;
   - открыта ступень 2 → `fixed_after_rule`;
   - открыта ступень 3 или задача не решена → `needs_example`.
   
   Задача, решённая верно с первой попытки, наблюдения не даёт: достаточно записи в `practice_attempts`.
4. `portrait.build` не меняй: он учитывает только `source` `auto` и `teacher`, поэтому числа демо не меняются. Проверь это тестом.

### A5. Страница «🧩 Тренажёр» — `ui/practice.py`

Функция `render(conn, L, lang, esc, badge, render_lines, students)`.

1. **Выбор ученика.** Список учеников бери только через переданный `students()` — это помощник из `app.py`. Дзета добавит в него фильтр по роли (ученик видит только себя), и тренажёр получит этот фильтр без правок.
2. **Режим «Разобрать свою ошибку»:**
   - список сохранённых работ ученика с ошибкой (`attempts.first_error_line IS NOT NULL`), свежие сверху;
   - работа показывается через `render_lines` с подсвеченной строкой;
   - поле ввода заполнено строками до ошибочной;
   - «Проверить» → `check_problem`;
   - при ошибке — кнопка «Ещё подсказка» (ступень 1 → 2 → 3);
   - при успехе — «Исправлено!» и запись исхода.
3. **Режим «Задания под слабое место»:** `targets_for` → `generate(n=3…5)` → задачи по одной, с тем же циклом «решение → проверка → подсказки».
4. **Тон для ученика:** мягкие формулировки без оценок. Показывать номер строки и подсказку, никогда — правильный ответ.
5. **Регистрация в `app.py`:**
   - импорт `from ui import practice as practice_view`;
   - `"practice"` в `PAGES` перед `"about"`;
   - в `PAGE_NAMES`: `"practice": L("🧩 Тренажёр", "🧩 Жаттықтырғыш")`;
   - в словаре последней строки: `"practice": lambda: practice_view.render(conn, L, lang, esc, badge, render_lines, students)`.

### A6. Блок в портрете учителя

1. `practice.summary(conn, student_id) -> dict`: по целевым тегам — сколько задач решено и сколько раз `self_fixed`, `fixed_after_rule`, `needs_example`. Вывод по правилу:
   - не меньше 60 % `self_fixed` при не меньше чем 3 задачах → «исправляет сам(а) по вопросу: правило знает, но не применяет — поможет привычка самопроверки»;
   - не меньше 50 % `needs_example` при не меньше чем 3 задачах → «нужен разбор темы: правило пока не сложилось»;
   - иначе «мало данных».
   
   Тон — действия, не характер.
2. `ui/practice.py: render_portrait_block(conn, student_id, L, lang)` — ничего не выводит, если данных нет. Вставка в `app.py`: одна строка в `portrait_teacher` сразу перед `st.header(L("3. Что пишет учитель", "3. Мұғалім не жазады"))`.
