# Агент Бета · Новые темы и типы ошибок

Ты — агент **Бета**. Твоё направление — ядро проверки.

Сейчас проверка знает три навыка: линейные уравнения, квадратные уравнения (включая дробно-рациональные) и упрощение выражений. Учителю нужен весь курс алгебры 8–9 классов.

Твоя задача — добавить темы так, чтобы каждая была отдельным модулем: вид задачи, правила ошибок, теги и советы на двух языках, тесты. Тема должна появляться в журнале, портрете и карте класса без правок их кода.

**Кратко**

- **Результат:** этап A — неравенства; этап B — системы уравнений, биквадратные уравнения, алгебраические дроби; на каждую тему не меньше 10 тестов.
- **Объём:** этап A — примерно 3–4 часа, этап B — 4–6 часов.
- **Зависимости:** нет.

### Проект

**Портрет ученика** — MVP команды на хакатоне VENTUREHACK 2026, трек «Образование». Веб-приложение для учителя математики на Streamlit. Автопроверка домашних работ по алгебре 7–9 классов (SymPy) записывает в *журнал наблюдений* ошибки, способы решения и привычки ученика. Из журнала и комментариев учителя собирается *портрет* «где слаб и как работать» и *карта класса*. Интерфейс на русском и казахском.

Репозиторий: https://github.com/SatbayevAman/venture-hack. Подробности — в `README.md`.

### Принципы — нарушать нельзя

1. **Модель только на входе и на выходе.** Языковая модель распознаёт почерк, размечает свободный текст учителя и переформулирует готовые советы. Всё, что считает и решает, — обычный код, поэтому любой вывод воспроизводим.
2. **Только словарь тегов.** Выводы об ученике — только коды из `core/tags.py`. Неизвестный тег `db.add_observation` превращает в `other` или `teacher_other`. Новый вид вывода — это новый тег в словаре: название, совет учителю и совет ученику на `ru` и `kk`.
3. **Доказательство у каждого вывода:** работа, задача, строка, цитата. Меньше 3 случаев — пометка «мало данных» вместо вывода.
4. **Тон.** Описываем действия («в 4 работах из 6 нет проверки»), а не характер. Наводящий вопрос никогда не называет ответ. Версия для ученика — мягкая.
5. **Приватность.** Псевдонимы вместо имён. Фото не сохраняются — только строки текста. Синтетические данные везде подписаны как синтетические.
6. **Без ключа API всё работает.** Новая функция с языковой моделью обязана иметь офлайн-путь или аккуратно отключаться с объяснением.
7. **Два языка.** Каждая строка интерфейса — через `L("рус", "қаз")`, в словарях — поля `ru` и `kk`. Все новые казахские тексты перечисли в отчёте: их вычитает носитель языка.

## Этап A — неравенства

### A1. Реестр видов задач

1. `core/kinds/__init__.py`: словарь `KINDS: dict[str, Callable] = {}` и регистрация модулей (`from . import inequality` → `KINDS["inequality"] = inequality.check`).
2. `core/checker.py`, функция `check_problem` — перед существующими ветками:
   ```python
   from .kinds import KINDS  # импорт внутри функции: модули видов сами импортируют checker
   if kind in KINDS:
       return KINDS[kind](statement, raw_lines, reference_len, reference_answer)
   ```
3. Вид возвращает обычный `CheckResult` со списком `LineResult`. Тогда экран проверки, `pipeline` и портрет работают без изменений.
4. Поле `true_answer` — список чисел или `None`: экран проверки форматирует его через `:g`. Текстовую запись ответа клади в `final`.

### A2. Разбор строк неравенств — `core/kinds/inequality.py`

1. **Знаки отношения:** `<`, `>`, `≤`, `≥`, `<=`, `>=`, `⩽`, `⩾`. Режь строку по знаку **до** `checker.normalize`, каждую часть нормализуй и разбирай `checker.parse` отдельно: белый список `parse` не пропускает `<` и `>`.
2. **Виды строк:**
   - неравенство;
   - «x ∈ …» и ответ в записи промежутков;
   - совокупность «x < 2 или x ≥ 3»;
   - связанное уравнение («x² − 5x + 6 = 0») и корни («x₁ = 2, x₂ = 3») — это критические точки;
   - строки со знаками промежутков («+ − +») — информационные, не проверяются;
   - метки «Ответ» и «Проверка» — как в `checker.normalize`.
3. **Разбор записи промежутков.** Формы: `(−∞; 2) ∪ [3; +∞)`, `[1; 5)`, `(−∞; +∞)`, `R`, `∅`, «нет решений». Скобки `( [ ) ]`, разделитель `;`, объединение `∪` или `U`, бесконечность `∞`, `+∞`, `−∞`, `oo`. Запятую как разделитель тоже поддержи, но осторожно: `checker.normalize` превращает `2,5` в `2.5`, поэтому промежутки разбирай по исходному тексту строки, до нормализации.
4. **Множество решений** — `sympy.solveset(rel, x, S.Reals)`. Сравнение — равенство множеств sympy; для нестабильных форм добавь численную проверку в точках.

### A3. Проверка и типы ошибок

Соседние строки-неравенства сравниваются по множеству решений на ℝ. Первая строка, где множества разошлись, — место ошибки. Тип определяй в таком порядке:

| Тег | Название (ru) | Правило |
|---|---|---|
| `ineq_flip` | Знак неравенства при умножении или делении на отрицательное | если в текущей строке сменить знак отношения на противоположный, множества совпадут |
| `ineq_div_var` | Деление неравенства на выражение с x | предыдущая строка = q(x) · текущая (как в `checker._division_detail`), и q зависит от x |
| `interval_choice` | Выбран не тот промежуток | критические точки верны, а множество совпадает с дополнением правильного (с точностью до концов) |
| `boundary` | Граница: строгое или нестрогое, точка вне ОДЗ | множества отличаются только конечным числом точек; если точка обнуляет знаменатель — `detail.domain` |
| `sign`, `calc`, `fsu` | существующие | переиспользуй существующие правила: смена знака одного слагаемого (`checker._flip_variants`); одно неверное число — отличается ровно одна граница промежутка; неверное раскрытие скобок (`checker._fsu_variants`) |
| `other` | существующий | ничего не подошло |

- Итоговый ответ сравнивается с решением условия. Если до ответа ошибок не было, а ответ неверен, классифицируй ошибку на строке ответа теми же правилами.
- Метод `interval_method` (метод интервалов) — если в решении есть критические точки или разложение на множители.
- Привычки `check_done` и `skip_steps` — как в `checker`.

### A4. Словарь

1. `SKILLS["inequality"] = {"ru": "Неравенства", "kk": "Теңсіздіктер"}`; в `SKILLS_SHORT` — «Неравенства» / «Теңсіздік».
2. Теги `ineq_flip`, `ineq_div_var`, `interval_choice`, `boundary` (kind `error`) и `interval_method` (kind `method`) с полями `ru`, `kk`, `teacher_ru`, `teacher_kk`, `student_ru`, `student_kk` — по образцу существующих. Учителю — конкретное действие: что дать, что спросить. Ученику — конкретное правило.
3. `CONFIRMS` — ключи для новых тегов, которые учитель может назвать в комментарии. `LEXICON` — основы слов: «знак неравенства», «промежут», «граница»; по-казахски «теңсіздік таңбасы», «аралық», «шекара».
4. `QUESTIONS` и ветвление в `question_for`. Вопрос указывает строку и направление, но не называет ответ. Пример для `ineq_flip`: «В строке {n} обе части умножены или разделены на отрицательное число. Что при этом происходит со знаком неравенства?»

### A5. Тесты — `tests/test_beta.py`, минимум

| Условие | Строки ученика | Ожидание |
|---|---|---|
| `2x − 3 > 5` | `2x > 8`, `x > 4`, `Ответ: (4; +∞)` | верно |
| `−3x < 6` | `x < −2` | `ineq_flip`, строка 1 |
| `2x − 3 > 5` | `2x > 5 − 3` | `sign`, строка 1 |
| `x² > 3x` | `x > 3` | `ineq_div_var`, строка 1 |

### B1. Системы уравнений — `core/kinds/system.py`, вид и навык `system`

- **Условие** в `problems.statement` — два уравнения через `;`: «x + y = 5; x − y = 1». Переменные x и y. Линейные системы и системы «одно квадратное + одно линейное» (9 класс).
- **Строки:**
  - система в одной строке через `;` или двумя строками с `{`, `⎧`, `⎩`;
  - одиночные уравнения;
  - выражения вида «y = 5 − x»;
  - значения вида «x = 3»;
  - ответ: «(3; 2)», «x = 3, y = 2», «нет решений», «бесконечно много решений».
- **Принцип проверки.** Σ — множество решений условия (`sympy.solve` или `nonlinsolve`). Каждая строка-уравнение должна быть **следствием** системы, то есть выполняться во всех точках Σ. Строка-система должна быть **равносильна** условию. Первая строка, где это нарушено, — ошибка.
- **Типы ошибок:**
  - `subst` — «Подстановка без скобок»: строка совпадает с подстановкой выражения из строки «y = …», если сменить знак одного слагаемого подставляемого выражения;
  - `swap_xy` — «Перепутаны x и y в ответе»;
  - `sign` и `calc` — какая одна правка (смена знака слагаемого или одно число) делает строку следствием системы;
  - `other`.
- **Методы:**
  - `substitution` — есть строка «переменная = выражение», а после неё строка с одной переменной;
  - `addition` — строка с одной переменной равна c₁·E₁ + c₂·E₂, где c₁ и c₂ не равны нулю.
- Навык `system`, теги, советы и вопросы на `ru` и `kk`; не меньше 10 тестов; задача с системой — в `EXTRA_ASSIGNMENTS`.

### B2. Биквадратные уравнения — `core/kinds/biquadratic.py`, вид и навык `biquadratic`

- Поддержи замену переменной: строка «t = x²» или «пусть x² = t».
- **Порядок проверки:**
  1. Строки в x до замены проверяются через `checker.check_equation`.
  2. Первое уравнение в t после подстановки t = x² должно совпасть с текущим уравнением в x как многочлен. Иначе ошибка замены — тег `subst`.
  3. Строки в t проверяются через `checker.check_equation` (переменную функция определит сама).
  4. Обратная замена («x² = 1 или x² = 4») и итоговые корни сравниваются с решением условия.
- **Типы ошибок:**
  - забыт ± → `lost_root` с `detail.pm`;
  - не отброшено отрицательное t («x² = −3 → x = ±√3») → новый тег `neg_t` «x² = t при t < 0 не имеет решений»;
  - потерянные корни → `lost_root`.
- Не меньше 10 тестов.

### B3. Алгебраические дроби — вид `expression`, навык `fractions`

- Новый вид задачи не нужен: `check_expression` уже сравнивает дробные выражения. Добавь навык `fractions` и тег `cancel_terms` — «Сокращение слагаемых вместо множителей».
- **Правило** в `classify_expr_step`, перед проверкой ФСУ. Для каждой дроби предыдущей строки, у которой числитель и знаменатель — суммы с общим слагаемым t, построй вариант (числитель − t)/(знаменатель − t). Если текущая строка тождественна предыдущей с такой заменой — это `cancel_terms`. Примеры: `(x + 2)/(x + 4)` → `2/4`; `(x² + 3x)/x` → `x² + 3`.
- Не меньше 10 тестов, включая случай, где правильное сокращение множителя ошибкой не считается.
