# Агент Дельта · Динамика и эффект советов

Ты — агент **Дельта**. Портрет сейчас — снимок: взвешенная доля ошибок по последним работам. Учителю важнее два вопроса: «становится ли лучше?» и «помог ли совет, который я применил?».

Твоё направление добавляет портрету время:
- траекторию по работам;
- честный интервал неопределённости;
- тренды на карте класса;
- модель знаний (BKT);
- замер эффекта советов.

**Кратко**

- **Результат:** раздел «6. Динамика» в портрете; интервалы; тренды ▼▲ на карте класса; отметка «совет применён» и эффект до/после; модель BKT.
- **Объём:** этап A — примерно 2–3 часа, этап B — 3–4 часа.
- **Зависимости:** нет.

### Проект

**Портрет ученика** — MVP команды на хакатоне VENTUREHACK 2026, трек «Образование». Веб-приложение для учителя математики на Streamlit. Автопроверка домашних работ по алгебре 7–9 классов (SymPy) записывает в *журнал наблюдений* ошибки, способы решения и привычки ученика. Из журнала и комментариев учителя собирается *портрет* «где слаб и как работать» и *карта класса*. Интерфейс на русском и казахском.

Репозиторий: https://github.com/SatbayevAman/venture-hack. Подробности — в `README.md`.

### Принципы — нарушать нельзя

1. **Модель только на входе и на выходе.** Языковая модель распознаёт почерк, размечает свободный текст учителя и переформулирует готовые советы. Всё, что считает и решает, — обычный код, поэтому любой вывод воспроизводим.
2. **Только словарь тегов.** Выводы об ученике — только коды из `core/tags.py`. Неизвестный тег `db.add_observation` превращает в `other` или `teacher_other`. Новый вид вывода — это новый тег в словаре: название, совет учителю и совет ученику на `ru` и `kk`.
3. **Доказательство у каждого вывода:** работа, задача, строка, цитата. Меньше 3 случаев — пометка «мало данных» вместо вывода.
4. **Тон.** Описываем действия («в 4 работах из 6 нет проверки»), а не характер. Наводящий вопрос никогда не называет ответ. Версия для ученика — мягкая.
5. **Приватность.** Псевдонимы вместо имён. Фото не сохраняются — только строки текста. Синтетические данные везде подписаны как синтетические.
6. **Без ключа API всё работает.** Новая функция с языковой моделью обязана иметь офлайн-путь или аккуратно отключаться с объяснением.
7. **Два языка.** Каждая строка интерфейса — через `L("рус", "қаз")`, в словарях — поля `ru` и `kk`. Все новые казахские тексты перечисли в отчёте: их вычитает носитель языка.

### База и журнал

Таблицы в `core/db.py`: `students`, `assignments`, `problems`, `submissions` (`source`: `synthetic` или `live`), `attempts`, `steps`, **`observations`**, `teacher_comments`, `tags`. Портрет нигде не хранится: он каждый раз считается заново из `observations`.

Одна строка журнала — это контракт между проверкой и портретом:

```json
{"student_id": 1, "submission_id": 42, "problem_id": 27, "line_no": 1, "kind": "error",
 "tag": "lost_root", "skill": "quadratic", "evidence": "x² = 7x  →  x = 7",
 "detail": {"f": "x", "division": true}, "source": "auto", "confidence": 0.9}
```

Поля и смысл существующих значений не меняются. Новые значения `source` допустимы (например, `practice`): `portrait.build` учитывает только `auto` и `teacher`, поэтому числа портрета от них не меняются.

## Этап A — обязательный минимум

### D1. Последовательности — `core/knowledge.py`

1. `sequence(conn, student_id, skill, tag) -> list[dict]` — работы ученика, в которых есть задачи этого навыка, по времени сдачи (от старых к новым). Для каждой работы: `{"sub_id", "work_no", "submitted_at", "error": 0 или 1}`.
   - Данные бери через `portrait._works`, `portrait._skills_per_work`, `portrait._obs` (только `source == "auto"` и `kind == "error"`). Тогда определение «работа с навыком» совпадает с портретом, а отметки учителя от Эпсилона учтутся автоматически.
2. `habit_sequence(conn, student_id, habit)` — то же для привычек: например, `check_done` по всем работам.

### D2. Интервал

`wilson(e, n, z=1.2816) -> tuple[float, float] | None` — 80-процентный интервал Уилсона для доли e из n. При n < 3 возвращает `None`, и интерфейс пишет «мало данных».

### D3. Тренд

`trend(seq) -> "down" | "up" | "flat" | None`:
- `None` при меньше чем 4 работах;
- иначе сравни ошибки во второй половине последовательности с первой:
  - `down` — во второй половине ошибок меньше хотя бы на 2 случая; для последовательностей из 4–5 работ — хотя бы на 1, и доля упала не меньше чем на 30 процентных пунктов;
  - `up` — наоборот;
  - иначе `flat`.

Пороги — константы в начале модуля.

### D4. Интервенции — `core/interventions.py`

Функция `ensure_schema(conn)`:

```sql
CREATE TABLE IF NOT EXISTS interventions (
    id INTEGER PRIMARY KEY,
    student_id INTEGER NOT NULL,
    rec_key TEXT NOT NULL,          -- ключ рекомендации из portrait.build: "quadratic:lost_root", "habit:check_done"
    applied_at TEXT NOT NULL,
    note TEXT,
    created_at TEXT NOT NULL
);
```

Функции:
- `mark_applied(conn, student_id, rec_key, applied_at, note)`;
- `list_for(conn, student_id)`;
- `effect(conn, student_id, rec_key) -> dict`:
  - для ключей вида `<навык>:<тег>` — доля работ с ошибкой до `applied_at` и после;
  - для `habit:<привычка>` — доля работ с этой привычкой до и после;
  - `ready = n_after >= 3`, иначе `need_more = 3 - n_after`.

### D5. Интерфейс — `ui/dynamics.py`

1. `rec_controls(conn, student_id, rec, L, lang, key)`:
   - совет не отмечен → маленькая форма «Совет применён»: дата (по умолчанию сегодня) и заметка;
   - отмечен → «Применён 20.09 · эффект: ждём ещё 2 работы» или «до: 4/6 (67 %) → после: 1/3 (33 %)».
2. `render_section(conn, p, L, lang)` — раздел «6. Динамика» (по-казахски тоже «6. Динамика»). Для каждой ошибки ученика, слабые места первыми:
   - полоска ✓✗ по работам с номерами ДЗ;
   - доля ошибок и интервал Уилсона;
   - тренд словами: «ошибок меньше, чем в начале», «ошибок больше», «без изменений»;
   - график накопленной доли — `st.line_chart` или Altair (он идёт вместе со Streamlit).
   
   Для привычки «проверка ответа» — то же самое.
3. Вставки в `app.py` — см. «Границы».

## Этап B — полная версия

### B1. BKT — `core/knowledge.py`

- **Модель.** Для пары «навык, тег» наблюдение по работе: «верно», если в работе нет этой ошибки. Параметры: p(L0), p(T), p(S), p(G); ограничения p(S) < 0.5 и p(G) < 0.5.
- **Подбор параметров** по данным всего класса: перебор по сетке (L0 от 0.1 до 0.9, T от 0.05 до 0.4, S от 0.05 до 0.3, G от 0.1 до 0.4; шаг 0.05–0.1), максимум правдоподобия. При меньше чем 10 наблюдениях — значения по умолчанию: 0.3, 0.15, 0.1, 0.2. Только numpy (он идёт вместе с pandas).
- **Траектория.** `bkt_trajectory(seq, params) -> list[float]` — P(навык освоен) после каждой работы. Формулы стандартные (Corbett & Anderson, 1994): апостериорная вероятность после наблюдения, затем переход с p(T).
- **Показ.** В разделе «Динамика»: «вероятность, что навык освоен: 0.35 → 0.52» рядом с полоской ✓✗ и объяснение модели одной строкой.

### B2. Переключатель модели портрета

Переменная окружения `PORTRAIT_MODEL=weighted|bkt`, по умолчанию `weighted`.
- При `bkt` в `portrait.build` слабое место — это случаев не меньше `MIN_CASES` и P(освоено) не больше 0.6. Формулировки прежние.
- При `weighted` код идёт по прежнему пути, тесты демо не меняются.

### B3. Динамика класса

На странице карты класса — блок «Динамика класса»: по каждому навыку доля учеников с трендом ▼ и ▲.

### B4. Проверка на синтетике

В тесте (не в сиде) смоделируй ученика, который после совета три работы подряд решает без ошибки. Ожидания: тренд `down`, P(освоено) растёт, `effect` показывает снижение доли ошибок.

- `interventions.effect`: доли до и после; `ready` и `need_more`.
- BKT: одно обновление посчитано вручную; подобранные параметры в допустимых границах.
- `class_map`: у ячеек есть `trend`, остальные поля прежние.
- Модель по умолчанию: числа демо прежние.
- **Сценарий улучшения:** база через `seed.build`, затем 3 живые сдачи ДЗ №7 для Айгерим с верным решением задачи «x² = 7x» через разложение на множители. Ожидания: тренд `lost_root` — `down`, P(освоено) растёт.

## Как это выглядит на демо

## Подводные камни

- Карта класса вызывает `portrait.build` для каждого ученика. Тренды не должны заметно замедлять страницу: для 8 учеников это не проблема, для 30 и больше кэшируй по `(student_id, число наблюдений)`.
- ▼ означает «ошибок меньше», это хорошо. Не окрашивай ▼ красным.
- Для ошибок знаменатель — работы с задачами этого навыка, а не все работы (как в портрете).
