# Агент Альфа · Надёжное распознавание фото

Ты — агент **Альфа**. Твоё направление — путь «фото тетради → строки решения».

Сейчас он работает только в идеальном случае: модель вернула строки, учитель перечитал их в текстовом поле. Твоя задача — чтобы на настоящих тетрадях:
- учитель сразу видел, где распознавание сомнительно, и быстро это правил;
- портрет не делал выводов из непроверенных строк;
- у команды были честные цифры точности.

**Кратко**

- **Результат:** вкладка «Фото тетради», где строки проверяются рядом с фото; уверенность каждой строки; журнал распознаваний; метрики точности для слайда.
- **Объём:** этап A — примерно 2–3 часа, этап B — 3–5 часов.
- **Зависимости:** нет.

### Проект

**Портрет ученика** — MVP команды на хакатоне VENTUREHACK 2026, трек «Образование». Веб-приложение для учителя математики на Streamlit. Автопроверка домашних работ по алгебре 7–9 классов (SymPy) записывает в *журнал наблюдений* ошибки, способы решения и привычки ученика. Из журнала и комментариев учителя собирается *портрет* «где слаб и как работать» и *карта класса*. Интерфейс на русском и казахском.

Репозиторий: https://github.com/SatbayevAman/venture-hack. Подробности — в `README.md`.

### Принципы — нарушать нельзя

1. **Модель только на входе и на выходе.** Языковая модель распознаёт почерк, размечает свободный текст учителя и переформулирует готовые советы. Всё, что считает и решает, — обычный код, поэтому любой вывод воспроизводим.
2. **Только словарь тегов.** Выводы об ученике — только коды из `core/tags.py`. Неизвестный тег `db.add_observation` превращает в `other` или `teacher_other`. Новый вид вывода — это новый тег в словаре: название, совет учителю и совет ученику на `ru` и `kk`.
3. **Доказательство у каждого вывода:** работа, задача, строка, цитата. Меньше 3 случаев — пометка «мало данных» вместо вывода.
4. **Тон.** Описываем действия («в 4 работах из 6 нет проверки»), а не характер. Наводящий вопрос никогда не называет ответ. Версия для ученика — мягкая.
5. **Приватность.** Псевдонимы вместо имён. Фото не сохраняются — только строки текста. Синтетические данные везде подписаны как синтетические.
6. **Без ключа API всё работает.** Новая функция с языковой моделью обязана иметь офлайн-путь или аккуратно отключаться с объяснением.
7. **Два языка.** Каждая строка интерфейса — через `L("рус", "қаз")`, в словарях — поля `ru` и `kk`. Все новые казахские тексты перечисли в отчёте: их вычитает носитель языка.

### База и журнал

Таблицы в `core/db.py`: `students`, `assignments`, `problems`, `submissions` (`source`: `synthetic` или `live`), `attempts`, `steps`, **`observations`**, `teacher_comments`, `tags`. Портрет нигде не хранится: он каждый раз считается заново из `observations`.

Одна строка журнала — это контракт между проверкой и портретом:

```json
{"student_id": 1, "submission_id": 42, "problem_id": 27, "line_no": 1, "kind": "error",
 "tag": "lost_root", "skill": "quadratic", "evidence": "x² = 7x  →  x = 7",
 "detail": {"f": "x", "division": true}, "source": "auto", "confidence": 0.9}
```

Поля и смысл существующих значений не меняются. Новые значения `source` допустимы (например, `practice`): `portrait.build` учитывает только `auto` и `teacher`, поэтому числа портрета от них не меняются.

5. Страница интерфейса — модуль `ui/<имя>.py` с функцией `render(...)`. `ui/__init__.py` — пустой файл; если его ещё нет, создай пустым. В `app.py` добавляются только импорт, ключ в `PAGES`, подпись в `PAGE_NAMES` и запись в словаре страниц в последней строке.

## Этап A — обязательный минимум

### A1. Детальное распознавание — `core/llm.py`

1. Добавь `recognize_detailed(cfg, image_bytes, problems, passes=1) -> dict[int, list[dict]]`. Элемент строки — `{"text": str, "unsure": list[str]}`: сырой ответ модели.
2. Новый промпт на основе `OCR_PROMPT`: для каждой строки модель возвращает `text` и `unsure` — список неразборчивых фрагментов; неразборчивый символ в `text` заменяет на `?`. Остальные правила промпта сохрани: не исправлять ошибки ученика, не решать, не добавлять строк, не переписывать условие, если его нет в тетради. Схема ответа:
   ```json
   {"problems": [{"number": 1, "lines": [{"text": "x² = 7x", "unsure": []}]}], "unassigned": []}
   ```
3. Надёжный JSON. Если ответ не разобрался — один повторный запрос «верни только JSON по схеме», с текстом прошлого ответа. Вторая неудача — `LLMError` с понятным текстом на русском.
4. `recognize()` оставь с прежней сигнатурой и форматом `{номер задачи: [строки]}`: пусть вызывает `recognize_detailed` и отбрасывает всё, кроме `text`. На `recognize()` опирается `evaluate.py`.
5. Не проси модель оценивать уверенность числом: модели плохо откалиброваны. Уверенность считает код (шаг A2).

### A2. Уверенность строк — `core/ocr.py`

1. Константа `UNSURE = 0.8`: строка ниже порога «требует проверки».
2. `clean_text(text) -> str` — предобработка ответа модели до нормализации: обрывки LaTeX (`\cdot`, `\sqrt{…}`, `^{2}`, `\le`, `\ge`, `\pm`), лишние пробелы. Только то, что реально встречается; каждое правило покрой тестом.
3. `score_lines(lines) -> list[dict]` добавляет каждой строке `confidence` и `flags`:
   - `?` в тексте или непустой `unsure` → флаг `illegible`, `confidence` не выше 0.4;
   - строка не разбирается → флаг `unparsable`, не выше 0.3. «Не разбирается» значит: `checker.normalize(text)` не дал метку (`answer`, `check`, `domain`, `rejected`), и хотя бы одна часть `norm.text`, разрезанного по `=`, `|` и `;`, бросает `checker.ParseError` в `checker.parse`. Перед разбором замени `±` на `+`;
   - иначе `0.95`.
4. `unverified(ocr_raw, answers) -> dict[tuple[int, int], float]` — строки, которые пришли из распознавания с `confidence` ниже `UNSURE` и не были исправлены учителем (текст совпадает после `strip()`). Ключ — `(problem_id, line_no)`. Номер строки считай так же, как `checker`: с 1, пропуская пустые строки.

### A3. Вкладка «📷 Фото тетради» — `app.py`, блок `with tab_photo:`

   - «Строка» — редактируется;

### A4. Журнал распознаваний и честность выводов

1. `core/ocr_store.py`, таблица:
   ```sql
   CREATE TABLE IF NOT EXISTS ocr_lines (
       id INTEGER PRIMARY KEY,
       submission_id INTEGER NOT NULL,
       problem_id INTEGER NOT NULL,
       line_no INTEGER NOT NULL,
       ocr_text TEXT NOT NULL,
       final_text TEXT,
       confidence REAL NOT NULL,
       flags TEXT,
       edited INTEGER NOT NULL,
       created_at TEXT NOT NULL
   );
   ```
   Функции:
   - `ensure_schema(conn)`;
   - `save(conn, submission_id, ocr_raw, answers)`;
   - `stats(conn) -> dict`: доля правленых строк, доля неуверенных, доля правленых среди неуверенных.
2. `core/pipeline.py`, `record_submission(..., line_confidence=None)`. Если строка первой ошибки задачи есть в `line_confidence` и её уверенность ниже `ocr.UNSURE`, наблюдение ошибки пишется с `confidence = 0.6` и `detail["ocr_unverified"] = True`. При `None` поведение прежнее — демо и тесты не меняются. `UNSURE` импортируй внутри функции, чтобы не создать циклический импорт.
3. `app.py`, обработчик кнопки «Записать в журнал и обновить портрет»:
   - в вызов `pipeline.record_submission(...)` добавь `line_confidence=ocr.unverified(ss.get("ocr_raw") or {}, chk["answers"])`;
   - сразу после вызова: если есть `ss.get("ocr_raw")`, вызови `ocr_store.save(...)`, затем `ss.pop("ocr_raw", None)`.
4. `app.py`, вывод результатов проверки. Внутри `if fe:` после блока «Наводящий вопрос ученику» добавь предупреждение, если строка первой ошибки неуверенная и не правилась: «⚠️ Ошибка найдена в строке, которую распознавание прочитало неуверенно. Сверьте её с фото перед записью.»

### A5. Метрики — `evaluate.py`

1. Необязательная колонка `problem` в `labels.csv` — номер задачи на фото, по умолчанию 1. Нужна для фото с несколькими задачами. Старый формат файла продолжает работать.
2. Новые метрики:
   - CER — доля посимвольных ошибок по нормализованным строкам (своя функция Левенштейна, без зависимостей);
   - сколько строк получили флаг и сколько из них действительно ошибочны — для калибровки `UNSURE`;
   - время распознавания одного фото.
3. `--out eval/results.md` — таблица результатов для слайда: дата, модель, число фото и строк, все метрики.
4. `--draft photo.jpg --statement "…" [--kind equation]` — распознаёт фото и дописывает в `labels.csv` черновую строку с пометкой `draft`, а человек правит эталон. Так команда быстрее разметит 30 фото.

## Этап B — полная версия

- **B1. Два прочтения.** При `passes=2` второй запрос идёт с другой формулировкой промпта. Строки выравниваются `difflib.SequenceMatcher` по нормализованному тексту. Расхождение → флаг `disagree`, `confidence` не выше 0.5, оба варианта в `alternatives`; в таблице — выбор варианта. Переключатель «Два прочтения (точнее, дороже)», по умолчанию выключен.
- **B2. Строки без задачи.** Если модель не отнесла строки к задаче (`unassigned`), покажи их отдельным списком с выбором задачи для каждой строки.
- **B3. Калибровка порога** по `eval/`. Подбери `UNSURE`, при котором не меньше 90 % реальных ошибок распознавания попадают в «требуют проверки» при минимуме ложных тревог. Итог и таблицу «порог → полнота → ложные тревоги» запиши в `docs/alpha.md`.
- **B4. Синтетический набор для дымового теста.** Скрипт `eval/make_synthetic.py` рисует строки решений из `core/seed.py` рукописным шрифтом с кириллицей (например, Caveat, лицензия OFL) в `eval/synthetic/*.png` и создаёт разметку. Набор помечен как синтетика; цифры для слайда — только по реальным фото.
- **B5. Статистика правок на экране проверки:** «в этой работе исправлено 2 строки из 14».

## Как это выглядит на демо

1. Учитель фотографирует тетрадь.
2. Через несколько секунд рядом с фото появляется таблица строк; две строки помечены ⚠️.
3. Учитель правит одну строку и нажимает «Проверить».
4. Видит первую ошибку и наводящий вопрос.

На слайд — `eval/results.md`: «N фото, X % строк без правки, Y % первых ошибок совпало».

## Подводные камни

- Streamlit не даёт менять значение виджета после его создания в том же прогоне. В `lines_*` пиши только из блока фото (он выше текстовой вкладки) и перед `st.rerun()`.
- Номер строки в `checker` пропускает пустые строки. Нумеруй так же, иначе `line_confidence` не совпадёт.
- Не храни фото и не пиши байты изображения в базу или логи.
