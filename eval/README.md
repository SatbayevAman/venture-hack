# Разметка реальных работ

`labels.csv` — эталон для `python evaluate.py` и страницы «Качество». Обе считают точность одной функцией `core/quality.py` → `reference_accuracy`, поэтому цифры совпадают.

Только с согласия одноклассников; в файл — без имён.

## Как добавить работу

1. Сфотографируйте решение и положите фото в `eval/photos/`, например `eval/photos/01.jpg`. Папка `eval/photos/` в `.gitignore` — фото в репозиторий не попадают.
2. Добавьте строку в `labels.csv` (UTF-8, одна строка — одна задача): вручную или черновиком через `--draft` (см. ниже). Строки решения — **ровно как написано в тетради, с ошибками**.
3. `python evaluate.py` — точность проверки на эталонных строках; `python evaluate.py --ocr` — плюс распознавание фото (нужен ключ API: `ANTHROPIC_API_KEY` или `OPENAI_API_KEY`).

## Колонки

| Колонка | Что писать |
|---|---|
| `photo` | путь к фото относительно `eval/`, например `photos/01.jpg`; пусто — только проверка, без распознавания |
| `problem` | номер задачи на фото, если на одном фото несколько задач; пусто — 1 |
| `kind` | вид задачи, см. ниже |
| `statement` | условие |
| `lines` | строки решения через ` \| ` |
| `error_line` | номер первой неверной строки; 0 — решение верное |
| `error_tag` | тег первой ошибки, см. ниже; пусто — сравнивается только номер строки |
| `status` | пусто или `draft` — черновик из `--draft`, эталон ещё не проверен человеком |

`problem` и `status` необязательны: файл без них тоже читается. Поле с запятой берите в двойные кавычки: `"x₁ = 3, x₂ = −2 | Ответ: (−2; 3)"`.

Черновики (`status=draft`) не входят в точность ни в `python evaluate.py`, ни на странице «Качество»; `evaluate.py` печатает, сколько их пропущено. Проверьте черновик по фото и сотрите `draft`.

## Виды задач (`kind`)

| `kind` | Вид | Как писать `statement` |
|---|---|---|
| `equation` | уравнение | `x² − 5x + 6 = 0` |
| `expression` | выражение, в том числе алгебраические дроби | `(a + 3)² − (a − 3)(a + 3)`, `(x² − 9)/(x² + 3x)` |
| `inequality` | неравенство | `2 − 3x < 11` |
| `system` | система уравнений | уравнения через «;»: `2x + y = 7; x − y = 2` |
| `biquadratic` | биквадратное уравнение | `x⁴ − 5x² + 4 = 0` |

Неизвестный `kind` проверяется как уравнение. Примеры строк по задачам ДЗ №8–11 из `core/seed.py`:

```csv
photo,problem,kind,statement,lines,error_line,error_tag,status
photos/08.jpg,1,inequality,2 − 3x < 11,−3x < 11 − 2 | −3x < 9 | x < −3 | Ответ: (−∞; −3),3,ineq_flip,
photos/08.jpg,2,inequality,x² − x − 6 ≤ 0,"x² − x − 6 = 0 | x₁ = 3, x₂ = −2 | Ответ: (−2; 3)",3,boundary,
,,system,2x + y = 7; x − y = 2,y = 7 − 2x | x − (7 − 2x) = 2 | 3x − 7 = 2 | 3x = 9 | x = 3 | y = 7 − 6 = 1 | Ответ: (3; 1),0,,
,,biquadratic,x⁴ − 5x² + 4 = 0,"Пусть x² = t | t² − 5t + 4 = 0 | t₁ = 4, t₂ = 1 | x² = 4 или x² = 1 | x = 2, x = 1 | Ответ: 1; 2",6,lost_root,
,,expression,(x² + 3x)/x,x² + 3,1,cancel_terms,
```

## Теги ошибок (`error_tag`)

Из `core/tags.py`, `TAGS` с `kind == "error"`:

| Тег | Ошибка |
|---|---|
| `lost_root` | Потеря корня |
| `extra_root` | Посторонний корень |
| `sign` | Знак при переносе или раскрытии скобок |
| `fsu` | Формулы сокращённого умножения |
| `calc` | Вычислительная ошибка |
| `other` | Другое |
| `ineq_flip` | Знак неравенства при умножении или делении на отрицательное |
| `ineq_div_var` | Деление неравенства на выражение с x |
| `interval_choice` | Выбран не тот промежуток |
| `boundary` | Граница: строгое или нестрогое, точка вне ОДЗ |
| `subst` | Подстановка без скобок |
| `swap_xy` | Перепутаны x и y в ответе |
| `neg_t` | x² = t при t < 0 не имеет решений |
| `cancel_terms` | Сокращение слагаемых вместо множителей |

## Запуск

```
python evaluate.py                                   # только проверка на эталонных строках
python evaluate.py --ocr                             # плюс распознавание фото
python evaluate.py --ocr --passes 2                  # два прочтения каждого фото
python evaluate.py --ocr --out eval/results.md       # таблица для слайда (markdown)
python evaluate.py --labels другой.csv               # другой файл разметки
python evaluate.py --draft photos/07.jpg --statement "x² = 5x" [--kind equation] [--problem 1]
```

`--draft` распознаёт фото (нужен ключ API; `--passes` тоже работает), проверяет строки и дописывает в `labels.csv` строку со `status=draft`: `error_line` и `error_tag` заполнены автопроверкой, их нужно сверить с фото. `--kind` — один из видов выше (по умолчанию `equation`), `--problem` — номер задачи на фото (по умолчанию 1).

С `--ocr` распознанные строки оцениваются с учётом `kind` (`ocr.score_lines(lines, kind)`): у неравенств, систем и биквадратных уравнений записи вроде «+ − +» или «Пусть x² = t, t ≥ 0» не помечаются «требует проверки» только потому, что их не разбирает общий разбор. Правила уверенности и порог `UNSURE` описаны в докстринге `core/ocr.py`; `evaluate.py --ocr` печатает таблицу «порог → полнота → ложные тревоги» для калибровки порога.

Вывод на текущем `labels.csv` (4 задачи без фото):

```
=== Итог ===
Задач в разметке (без черновиков)                    4
Первая ошибка (строка) на эталонных строках          4/4 = 100%
Первая ошибка (строка и тег) на эталонных строках    4/4 = 100%
```
