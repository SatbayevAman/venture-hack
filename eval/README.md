# Разметка реальных работ

1. Сфотографируйте решение, положите фото в эту папку, например `eval/photos/01.jpg` (папка `photos/` в `.gitignore` — фото не попадают в репозиторий).
2. Добавьте строку в `labels.csv`: путь к фото, номер задачи на фото (`problem`, по умолчанию 1), тип (`equation`/`expression`), условие, строки решения через ` | ` — **ровно как написано в тетради, с ошибками**, номер первой неверной строки (0 — если всё верно) и тег ошибки. На одном фото может быть несколько задач — тогда по строке на каждую с одним и тем же `photo` и разными `problem`. Старый формат без колонок `problem` и `status` тоже работает.
3. Быстрее через черновик: `python evaluate.py --draft photos/01.jpg --statement "x² = 5x" [--kind equation] [--problem 1]` — модель распознаёт фото и дописывает в `labels.csv` строку с пометкой `status=draft`. Сверьте строки с фото, поправьте `error_line`/`error_tag` и сотрите `draft`: черновики в метрики не входят.
4. `python evaluate.py` — точность проверки на эталонных строках; `python evaluate.py --ocr` — плюс распознавание фото (нужен ключ API); `--passes 2` — два прочтения; `--out eval/results.md` — таблица для слайда.

Что считает `--ocr`:

| Метрика | Что значит |
|---|---|
| Строк верно без правки (G1) | строка распознавания совпала с эталоном после нормализации (`checker.normalize`, без пробелов и регистра) |
| CER | посимвольные ошибки (расстояние Левенштейна) по нормализованным строкам / символов в эталоне |
| Помечено «требует проверки» | строки с `confidence < ocr.UNSURE` и сколько из них действительно ошибочны |
| Ошибочных строк под флагом | полнота флага: какую долю ошибок распознавания учитель увидел бы с ⚠️ |
| Первая ошибка по распознанному (G2) | строка первой ошибки по распознанным строкам совпала с эталоном |
| Время на одно фото | среднее и медиана, секунды |
| Калибровка | таблица «порог → полнота → ложные тревоги» для выбора `UNSURE` |

## Синтетический набор — `eval/synthetic/`

`python eval/make_synthetic.py` рисует строки решений из синтетической истории (`core/seed.py`) рукописным шрифтом Caveat (SIL OFL 1.1) на листе в клетку: 30 фото с одной задачей и одно фото с ДЗ №7 целиком. Разметка — `eval/synthetic/labels.csv` (`status=synthetic`).

**Это дымовой тест, а не цифры для слайда**: шрифт читается легче настоящего почерка. `python evaluate.py --ocr --labels eval/synthetic/labels.csv` проверяет, что путь «фото → строки → проверка» работает целиком; `evaluate.py` сам помечает такие результаты как синтетические.

Только с согласия одноклассников; в файл — без имён.
